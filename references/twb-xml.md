# Authoring .twb XML by script

A dashboard may have to be written as .twb XML by a script. Since 13 Nov 2026 Tableau Desktop 2026.3 is installed on the author's Mac, so open every scripted file there and read its errors with `scripts/tableau_errors.py`. This guide is built from one real file: `BREWERY_OPS.twb` in `~/Documents/obsidian/ankur_vault/BEVERAGE_ERP_IT_WORKSHOP/tableau_demo/` (8,609 bytes, one datasource, one worksheet, no dashboard), its README.md and the sibling scripts `gen_data.py` and `build_hyper.py`.


Update (12 Nov 2026): the inferred sections 5 (filters), 6, 7 and 8 were checked against real public workbooks saved by Tableau Desktop. Section 12 lists the sources and section 13 holds a skeleton for a two sheet dashboard with one filter action. Tableau Desktop is still not installed here, so even the skeleton is unproven until a copy of Tableau opens it.
## Evidence labels

- VERIFIED: quoted from BREWERY_OPS.twb exactly as it stands.
- verified from <repo/file>: quoted or measured from a real public workbook saved by Tableau Desktop (section 12 holds the source list and builds).
- README: stated in the README, not provable from the XML.
- INFERRED: from my knowledge of the Tableau format. Not in any file read. Treat as unproven.
- Important caveat: nothing proves that Tableau Desktop opened BREWERY_OPS.twb without a repair prompt. The README says "Should open in any newer version" and chose one sheet "to keep risk of won't open low". That is intent, not a test result. The same applies to the skeleton in section 13.
## 1. Document skeleton and version attributes

VERIFIED root and top level order:

```xml
<?xml version='1.0' encoding='utf-8'?>

<!-- BREWERY_OPS Tableau workbook (workshop demo asset)
     Source: synthetic data generated by gen_data.py
     Connects to: Data/brewery_flat.csv (packaged inside the .twbx)
     Open in Tableau Desktop 2022.4 or later. -->

<workbook source-build='2023.1.0 (20231.23.0214.0220)' source-platform='win' version='18.1' xmlns:user='http://www.tableausoftware.com/xml/user'>
  <preferences>
    <preference name='ui.encoding.shelf.height' value='24' />
    <preference name='ui.shelf.height' value='26' />
  </preferences>
  <datasources> ... </datasources>
  <worksheets> ... </worksheets>
  <windows source-height='30'> ... </windows>
</workbook>
```

Notes:
- Order used: preferences, datasources, worksheets, windows. A dashboard file adds a `<dashboards>` block between worksheets and windows (INFERRED, see section 7).
- `version='18.1'` is the document format version. The README ties it to Tableau 2022.4 or later (README). `source-build` and `source-platform='win'` are provenance labels. Tableau tolerates a build older or newer than itself in general (INFERRED), but a newer `version` than the opening Desktop supports will be refused.
- The XML comment sits before the root element. VERIFIED present. Tableau normally does not write one, so strip it if a repair prompt appears (INFERRED risk).
- Real Tableau output has no blank lines between elements and uses 2 space indent with single quoted attributes. The file here uses single quoted attributes throughout, which is valid XML either way.
- Not present in this file but normal in Tableau saves (INFERRED): `<document-format-change-manifest>`, `<repository-location>`, `<style>` at workbook level, `<worksheet ... >` extras like `<layout-options>` and `<simple-id uuid='{...}'/>`. Their absence is a risk, not a proof of failure.

- The manifest lists feature flags (`<IntuitiveSorting />`, `<MarkAnimation />` and so on). The set differs by build. Files from 2025.3.2 carry only a few flags. It looks safe to omit or to write a short list, but omission is not tested.
- verified from tableau/document-api-python test/assets/TABLEAU_10_TWB.twb and others: very old files use `version='9.3'` or `'10.1'` with no manifest, so Desktop reads those too.
## 2. Datasource and connection

VERIFIED datasource, federated connection and CSV (textscan) named connection:

```xml
<datasource caption='Brewery Operations' inline='true' name='brewery' version='18.1'>
  <connection class='federated'>
    <named-connections>
      <named-connection caption='brewery_flat' name='textscan.brewery'>
        <connection class='textscan' directory='Data' filename='brewery_flat.csv' filter-zero-byte-files='true' password='' server='' />
      </named-connection>
    </named-connections>
    <relation connection='textscan.brewery' name='brewery_flat.csv' table='[brewery_flat#csv]' type='table'>
      <columns gridOrigin='' header='yes' outcome='6'>
        <column datatype='string'  name='Batch_ID'     ordinal='0'  />
        <column datatype='string'  name='Style'        ordinal='1'  />
        ...
        <column datatype='real'    name='Cost_ZAR'     ordinal='17' />
      </columns>
    </relation>
  </connection>
```

Key points:
- The datasource `name='brewery'` is a plain word. Real Tableau saves use `name='federated.0abc123...'` (a federated id). The task note shows shelf references as `[federated.xxx].[none:Field:nk]`; this file instead uses `[brewery].[none:Style:nk]`. Both patterns are internally consistent only if the same name is used in `<datasources>` of each view, in `datasource-dependencies` and in every shelf and encoding reference.
- The textscan path is relative: `directory='Data'` and `filename='brewery_flat.csv'`. Inside a .twbx the Data folder sits beside the .twb (section 8).
- The relation table name `[brewery_flat#csv]` replaces the dot of the file name with `#`. VERIFIED. Keep that rule for any CSV.
- Relation columns carry `name` (raw CSV header), `datatype` and `ordinal` (zero based, no gaps). `outcome='6'` is copied as is. Its meaning is not documented here. Keep 6 for a CSV with a header row (INFERRED from a single sample).
- The VERIFIED datatypes used: `string`, `real`, `integer`, `date`. A datetime column would use `datetime` (INFERRED).
- `<aliases enabled='yes' />` follows the connection. VERIFIED.

VERIFIED, placed after all column and calculation elements at the end of the datasource:

```xml
<extract count='-1' enabled='true' units='records'>
  <connection author-locale='en_GB' class='hyper' default-settings='yes' dbname='Data/Extracts/brewery_flat.hyper' schema='Extract' tablename='Extract' update-time='2026-05-22 11:23:00.000'>
    <relation name='Extract' table='[Extract].[Extract]' type='table' />
  </connection>
</extract>
```

- The hyper file is built separately by `build_hyper.py` using `tableauhyperapi`. VERIFIED from the script header: it writes data/brewery_flat.hyper from the CSV so a .twbx can go to Tableau Public. Table is `Extract.Extract`, matching the `schema` and `tablename` attributes.
- The .twbx listing shows `Data\Extracts\brewery_flat.hyper` (131,072 bytes), so the zip path matches `dbname`.

## 3. Column elements (metadata)

Two groups follow the connection. Both VERIFIED.

Dimensions:

```xml
<column caption='Batch ID'    datatype='string'  name='[Batch_ID]'    role='dimension' type='nominal' />
<column caption='Date'        datatype='date'    name='[Date]'        role='dimension' type='ordinal' />
<column caption='Stage Order' datatype='integer' name='[Stage_Order]' role='dimension' type='ordinal' />
<column caption='Pass / Fail' datatype='string'  name='[Pass]'        role='dimension' type='nominal' />
```

Measures:

```xml
<column caption='Volume (HL)'    datatype='real' name='[Volume_HL]'   role='measure' type='quantitative' />
<column caption='Cost (ZAR)'     datatype='real' name='[Cost_ZAR]'    role='measure' type='quantitative' />
```

Rules visible in the file:
- `name` is the raw field wrapped in square brackets. `caption` is the human label (spaces, brackets and slashes allowed).
- `role` is `dimension` or `measure`. `type` is `nominal` (text), `ordinal` (date, ordered integer) or `quantitative` (numeric measures).
- All 18 relation columns are covered: 13 dimensions and 5 measures. Qty_Planned and Value are measures, Stage_Order is a dimension by choice.
- `default-format='p1'` on Pass Rate gives a one decimal percent. VERIFIED. Other format codes are INFERRED.
- Write one metadata `<column>` for every relation column. A missing one probably still opens, because Tableau infers it (INFERRED), but captions are lost.

## 4. Calculated fields

VERIFIED, all five:

```xml
<column caption='Pass Rate' datatype='real' default-format='p1' name='[Pass Rate]' role='measure' type='quantitative'>
  <calculation class='tableau' formula="SUM(IF [Pass] = 'Pass' THEN 1 ELSE 0 END) / SUM(IF [Pass] = 'Pass' OR [Pass] = 'Fail' THEN 1 ELSE 0 END)" />
</column>

<column caption='Distinct Batches' datatype='integer' name='[Distinct Batches]' role='measure' type='quantitative'>
  <calculation class='tableau' formula='COUNTD([Batch_ID])' />
</column>

<column caption='Failed Batches' datatype='integer' name='[Failed Batches]' role='measure' type='quantitative'>
  <calculation class='tableau' formula="COUNTD(IF [Status] = 'Failed' THEN [Batch_ID] END)" />
</column>

<column caption='Total LAE (Litres)' datatype='real' name='[Total LAE]' role='measure' type='quantitative'>
  <calculation class='tableau' formula='SUM([Volume_HL]) * 100 * 0.05' />
</column>
```

Quoting and escaping:
- VERIFIED: a formula without string literals uses single quoted attribute (`formula='COUNTD([Batch_ID])'`). A formula that contains single quoted strings switches to a double quoted attribute (`formula="... = 'Pass' ..."`). Follow that rule and no escaping of the quotes is needed.
- INFERRED: `&` must be written `&amp;`, `<` as `&lt;`, `>` is safe but `&gt;` is customary, a literal double quote inside a double quoted attribute as `&quot;`. The file has none of these characters in its formulas, so the escaping is not proven here. A formula such as `IF [Value] < [Qty_Planned] THEN ...` must be `&lt;`.
- Field references in a formula use the raw name in brackets (`[Batch_ID]`), not the caption. VERIFIED.
- Newlines inside formulas are written `&#13;&#10;` by Tableau (INFERRED). Keep formulas on one line to avoid it.
- `class='tableau'` marks a normal calculation. VERIFIED. Table calculations carry extra `<table-calc ...>` children in real files (INFERRED). LODs are written inline in the formula text (`{ FIXED [Batch_ID] : SUM([Value]) }`), no extra element (INFERRED).
- Calc `datatype` must match the result (`real`, `integer`, `string`, `boolean`, `date`). Pass Rate is `real`, counts are `integer`. VERIFIED usage.
- Naming: verified from real files, Desktop names a calculation `[Calculation_<digits>]` (for example `[Calculation_3868029180918833158]` in finn_server_2023.twb) or `[Calculation_<32 uppercase hex>]` (for example `[Calculation_25537AACABF642E3970A2622F6FEAD50]` in cwtwb examples and covid.twb) and keeps the friendly label in `caption`. A copied field keeps a readable name, for example `[Dummy (copy)_3868029180918870023]`, so spaces and brackets in a name do occur in real files. This file uses the friendly name straight in `name`, for example `[Pass Rate]`. That form was never seen written by Desktop. Prefer `[Calculation_<digits>]` with a `caption`.
- README confirms the calc list: Pass Rate, Distinct Batches, Failed Batches, Active Batches (not quoted above, same shape as Failed Batches) and Total LAE.

### Structure

- `<table>` holds `<view>`, `<style />`, `<panes>`, `<rows>` and `<cols>` in that order. VERIFIED.
- `<view><datasources>` lists the datasources used by name. `<datasource-dependencies>` repeats every field the sheet touches, including any calculated field with its full `<calculation>`. A sheet that uses a field not listed here is a classic cause of load failure (INFERRED).
- `<aggregation value='true' />` means aggregate measures. VERIFIED.

### Column instances

Each field on a shelf needs a `<column-instance>`. VERIFIED rules from the three samples:
- Name pattern: `[<derivation prefix>:<Field>:<kind>]`.
- Dimension, no derivation: `[none:Style:nk]` with `derivation='None'`, `type='nominal'`. The `nk` suffix means nominal key.
- Calculated measure: `[usr:Distinct Batches:qk]` with `derivation='User'`, `type='quantitative'`. The `qk` suffix means quantitative key. Calcs carry the `usr` prefix and the aggregation is already inside the formula.
- `pivot='key'` on all three.
- Full derivation table, counted across 8 real workbooks (DS4Earth, finn_server_2023, covid, hacto, filtering, shapes_test, bpb Go To URL, cwtwb example). Each row is `derivation` then name prefix then suffix then `type`:

| derivation | prefix | suffix | type | note |
| --- | --- | --- | --- | --- |
| None | none | nk | nominal | dimension as is |
| None | none | qk | quantitative | continuous number, such as `[none:Month:qk]` |
| Sum | sum | qk | quantitative | most common measure |
| Avg | avg | qk | quantitative | |
| Max | max | qk | quantitative | |
| Attribute | attr | nk | nominal | ATTR() on a shelf |
| User | usr | qk or nk or ok | follows the calc | calculated field instance |
| Month | mn | ok | ordinal | discrete month |
| MY | my | ok | ordinal | month and year, discrete |
| MDY | md | ok | ordinal | exact date, discrete |
| Month-Trunc | tmn | qk | quantitative | continuous month |
| InOut | io | nk | nominal | set membership |

- The year derivation `yr` guessed earlier was not seen in these files. Treat it as unproven.
- The suffix after a second colon, as in `[usr:Rank Asc (copy):qk:1]`, marks a second instance of the same field and appears only in table calculation files.
- The `column-instance` for a field must also appear in `datasource-dependencies`. verified from DS4Earth.twb: each worksheet lists only the `column` and `column-instance` pairs it uses.
- A measure on a shelf is `[sum:Sales:qk]` with `derivation='Sum'`, so a plain numeric field needs no calculation.

### Shelf syntax

- Rows and columns text is `[datasource name].[column-instance name]`. VERIFIED: `[brewery].[none:Style:nk]`. With a real federated id it reads `[federated.0abc...].[none:Style:nk]`.
- Several fields on one shelf are joined by ` / ` (nesting) or ` + ` (side by side) (INFERRED): `([brewery].[none:Stage_Order:ok] / [brewery].[none:Stage:nk])`.
- The datasource name in a shelf reference must equal the `name` on the datasource. The caption is not used.

### Marks pane and encodings

- `<mark class='Automatic' />` VERIFIED. Other classes (INFERRED): `Bar`, `Line`, `Area`, `Circle`, `Square`, `Text`, `Gantt`, `Pie`, `Map`, `Polygon`.
- `<encodings>` lists channel children. VERIFIED only `<text column='...' />`. INFERRED siblings: `<color column='...' />`, `<size column='...' />`, `<label ... />`, `<tooltip ... />`, `<lod column='...' />`, `<detail column='...' />`.
- Encoding column text uses the same `[ds].[instance]` form as shelves. VERIFIED.
- A pane with `class='Bar'` plus a `<color>` encoding and a `<style>` block of `<style-rule element='mark'>` carries custom palettes (INFERRED, not scripted here).

```xml
    </style>
  </pane>
</panes>
```

- A worksheet `<style />` may be empty. Format rules are `<style-rule element='...'>` with `<format attr='...' value='...' />` children. Seen elements: `header`, `mark`, `pane`, `axis`, `table`. Seen attributes: `mark-color`, `mark-labels-show`, `height-header`, `minwidth`, `maxwidth`, `aspect`.
- A custom sheet title is `<layout-options><title><formatted-text><run ...>text</run></formatted-text></title></layout-options>` as the first child of `<worksheet>`. A worksheet ends with `<simple-id uuid='{...}' />`. Both verified from DS4Earth.twb.
- Encoding of size by a field uses `<encoding attr='size-bar' field='...' type='centersize' />` inside a `style-rule element='mark'` (DS4Earth.twb).
- In real files the `<column>` and `<column-instance>` elements inside `datasource-dependencies` are sorted by name. Order is not known to matter.

### Window content model, seen in a Desktop load error (13 Nov 2026, Desktop 2026.3)

Desktop 2026.3 printed the content model of `<window>` when a generated file broke it: `((cards,viewpoint?,simple-id)|(viewpoints,active,device-preview,simple-id))`. A worksheet window is cards, an optional viewpoint, simple-id. A dashboard window is viewpoints, active, device-preview, simple-id. Desktop picks the branch from the first child, so a dashboard window must start with `<viewpoints>` (an empty `<viewpoints />` is fine for a text only dashboard). `device-preview` was optional in practice: windows without it loaded. The official XSD for each release lives at github.com/tableau/tableau-document-schemas; validate against it after replacing `_.fcp.<Flag>.true...` prefixes with the plain name and dropping the `.false...` forms.

### How x, y, w and h are scaled (corrects the earlier text)

- All four are integers in a 0 to 100000 space measured against the WHOLE dashboard, not against the parent zone. The earlier note that coordinates were relative to the parent was wrong. Proof from DS4Earth.twb: zone 13 and its parent flow zone 10 both say `x='800'`. Zone 22 sits at `x='51308'`, which is 800 plus the sibling width 50508.
- The pixel size comes from `<size>`: `fixed-size='886'` on zone 22 matches `w='47892'` times 1850 pixels divided by 100000. That is a check a generator can run.
- Pixel size and layout kind: `<size ... sizing-mode='fixed' />` for a fixed canvas. `preset-index` appears when a device preset was picked (covid.twb has 16, finn_server_2023.twb has 1). Other `sizing-mode` values seen: `vscroll` (phone layout, no width limits).
- Margins: the outer flow zone is `x='1000' y='1000' w='98000' h='98000'` in a root `layout-basic` that is `x='0' y='0' w='100000' h='100000'` (finn_server_2023.twb). Children of a flow must sum to the flow size in its direction.
- Root rule: a tiled layout is `layout-basic` root, then `layout-flow` with `param='horz'` or `param='vert'`, then sheet zones. In DS4Earth.twb the first tiled zone is not wrapped in a layout-basic root, so the root wrapper is not strictly needed, but covid.twb and finn_server_2023.twb both wrap.

## 8. How .twbx packs

VERIFIED from `unzip -l BREWERY_OPS.twbx` (549,286 bytes unpacked, the file itself 93,844 bytes):

```
Data\batches.csv
Data\brewery_flat.csv
Data\inventory.csv
Data\qc_samples.csv
Data\stage_events.csv
Data\Extracts\brewery_flat.hyper
BREWERY_OPS.twb
```

- A .twbx is a plain zip. It contains one .twb at the root plus a `Data` folder that mirrors every relative path used in connections (`directory='Data'` and `dbname='Data/Extracts/...'`).
- Extracts live in `Data/Extracts/`. CSVs live in `Data/`.
- Entry names contain backslashes in this listing, which means the zip was made on Windows or by a tool that wrote Windows paths. Tableau accepts forward slashes (INFERRED). For a script on macOS use Python `zipfile` and write forward slashes. Do not copy the backslash style.
- Build recipe (INFERRED, simple): `zip -r BREWERY_OPS.twbx BREWERY_OPS.twb Data` run from the folder holding both. The .twb must sit at the root of the archive, not inside a subfolder.
- The README states the .twb is "same as inside the .twbx". The .twb file next to the .twbx is a convenience copy.
- If Desktop reports a missing data source, the README advice is to re-point it to the `Data/` folder inside the unzipped package (README).
- Tableau Public requires extracts, not live textscan connections (build_hyper.py docstring). The .twbx here carries both the CSV and the hyper.


### Second twbx sample

verified from tableau/document-api-python test/assets/TABLEAU_10_TWBX.twbx (saved by Desktop 10 on a Mac in 2016):


- The .twb sits at the archive root. Data sit under `Data/` with forward slashes in a Mac made file, so forward slashes are normal. The earlier worry about backslash entries is settled: write forward slashes.
- Files that real Desktop saves put in a .twbx: the .twb, `Data/Datasources/` or `Data/Extracts/` for extracts, `Data/<folder>/` for flat files. Dashboard images probably go under `Image/` (INFERRED, not seen here).
- The `<connection directory=...>` inside the .twb is rewritten to a path relative to the archive (`Data/...`) by Desktop on packaging. A generator must write that relative path itself.
## 9. Workflow for a scripted workbook

1. Generate data with a deterministic script (seed fixed) and write the CSV. The brewery example has 1,908 flat rows and 18 columns, long format, so one table drives every sheet.
2. Optionally build the .hyper with `tableauhyperapi` so the types match the relation columns.
3. Write the .twb from a template string with these parts filled in: datasource name, relation columns (name, datatype, ordinal), metadata columns, calculated fields, worksheets, windows.
4. Keep one datasource name everywhere. Build the shelf strings from it.
5. Zip to .twbx with forward slashes.
6. Validate that the XML is well formed (`python3 -c "import xml.dom.minidom,sys; xml.dom.minidom.parse(sys.argv[1])" file.twb`) and that every `[ds].[instance]` in rows, cols and encodings has a matching `column-instance` in the same worksheet.
7. Ask the user to open it in Desktop. Report the first repair prompt text back verbatim, because that points to the exact attribute at fault.

## 10. Risks that make a hand written twb fail to open

Ordered by how likely they are to bite. "VERIFIED risk" means the Brewery file shows the pattern and it is unproven; the others are from general knowledge.

1. Never tested in Desktop. The README says the .twb ships with one sheet "to keep risk of won't open low", which admits risk. Treat every untested piece below as suspect.
2. Datasource name `brewery` (VERIFIED pattern) instead of a federated id. Every real Desktop file uses `federated.` plus 28 lowercase alphanumerics, so use that and update every reference.
3. Calculated field `name` with spaces, such as `[Pass Rate]` (VERIFIED pattern). Real files use `[Calculation_<digits>]` or `[Calculation_<hex>]`.
4. Missing `column-instance` for a field on a shelf, or a name that does not follow `[prefix:Field:suffix]`. Prefix, derivation and type must agree (`usr` with `User`, `none` with `None`).
5. A field used on a sheet but missing from `datasource-dependencies`, or a calculated field in dependencies whose formula differs from the datasource copy.
6. Formula text issues: unescaped `&` or `<`, a double quote inside a double quoted attribute, a reference by caption instead of raw name.
7. Relation columns that do not match the CSV header exactly (case, order, count) or an `ordinal` gap. The CSV must have the header row because `header='yes'`.
8. Hyper extract mismatch: types or column order not equal to the relation, a wrong `dbname`, or a stale `update-time`. Fix by removing the `<extract>` element and shipping live CSV.
9. Datatype mismatch: `integer` declared on a column whose CSV has decimals, or `date` on text that is not ISO (`YYYY-MM-DD` as in the sample data).
10. Window name not equal to sheet name, or a worksheet with no window, or a dashboard zone naming a sheet that does not exist.
11. Dashboard zones: duplicate `id`, children that do not sum to the parent, coordinates written relative to the parent instead of the whole dashboard, an action whose dashboard or sheet name differs by one character. Most likely failure of any dashboard scripted without a test.
12. Version drift: `version` newer than the opening Desktop. 18.1 is used by Desktop 2019.3 through 2025.3.2, so 18.1 is safe for every release since 2019.
13. Archive layout: the .twb not at the zip root, Data paths not matching `directory`, backslash entry names (a Mac made twbx uses forward slashes).
14. Missing `simple-id` elements, thumbnails and the format manifest. Every real Desktop save has them and no generated file is proven without them. Add `simple-id` GUIDs (cheap) before thumbnails. A leading XML comment is normal.
15. Encoding: keep UTF-8 without a BOM. Captions with non ASCII characters need no escaping in UTF-8.

## 11. Safe minimal strategy

- Ship one worksheet first, exactly like BREWERY_OPS.twb. The README states the intent: ship one starter sheet, then drag the four chart sheets and the dashboard in Desktop, about 30 seconds each.
- Put the rest of the design in a build kit (sheet recipes with Columns, Rows, Colour, Sort and Filter lines) so a person with Desktop can finish the dashboard. The README does this for four sheets: Process Flow (stacked bar), Batch Tracker (Gantt), QC Pass Rate by Stage (bar with a red, amber, green colour) and Inventory Shrink (variance bars).
- Add sheets to the XML only one at a time and ask for a test open after each one.
- Keep a clean copy of the last good .twb. Changing several things between tests makes a repair prompt impossible to trace.

## 12a. Generator packages and tools

- tableaudocumentapi (PyPI, tableau/document-api-python): version 0.11 of 7 Nov 2022, MIT, support level As-Is (unsupported by Tableau), repo not archived but no release since 2022. Its README says it cannot create workbooks from scratch. It edits connections, datasource names and field captions in an existing TWB, TWBX, TDS or TDSX. It cannot add dashboards, so it is no help for generation. Its test assets are useful real files (rows above).
- aidatacooper/cwtwb: Python toolkit and MCP server that writes workbooks from code or agent calls. 51 stars, pushed 6 Nov 2026, AGPL-3.0. No claim of a real Desktop test seen in the README. Its example output is single line XML with no thumbnails, which is not how Desktop writes. AGPL needs care before any reuse.
- weisberg/pytableau: SDK to patch and validate workbooks, with a YAML spec route. MIT, 7 stars. Its own advice is template first: build a viz in Desktop, then parameterise it.
- laviDrori0702/tableau-dashboard-creator-skill (and a vendored copy in Kilo-Org/kilo-marketplace): a Claude skill that builds an experimental .twbx. It states the output as a whole is not tested in Desktop and the validators "are not Tableau". Individual constructs are attested against workbooks saved by Desktop 2025.1.
- vizlumina-eng/tableau-public-pipeline: single author CSV to .twbx pipeline for Tableau Public. Claims 28 iterations and links a live viz. Not read in detail.
- Verdict: no mature, widely used from-scratch .twb generator exists. The safest route stays template first: take a real Desktop file, change names and values by script, keep every unknown block as saved.

## 13. Known-good style skeleton: two sheets, one dashboard, one filter action

Built by reducing the verified structures above (DS4Earth.twb for the datasource, action, group, filter and windows). It is well formed XML and every `[ds].[instance]` reference has a matching `column-instance` (checked by script), but it has NOT been opened in Tableau Desktop. It leaves out the manifest, `metadata-records`, thumbnails and device layouts. If a repair prompt appears, first add the omitted parts from section 1, then the thumbnails.

Rules baked into it:
- One datasource id `federated.<28 chars>` used in every reference, one textscan name `textscan.<28 chars>`.
- Sheet A (`Sales by Region`) is the action source. Sheet B (`Sales by Category`) holds the action filter and slice.
- The datasource holds the hidden `Action (Region)` group that Desktop creates for the filter.
- The dashboard names both sheets once as zones. The action names the dashboard and the source sheet exactly as written.
- Coordinates are in whole dashboard space: 1000 plus 49000 plus 49000 equals 99000, then 1000 margin on both ends.
- Zone ids 2 to 5 are unique. The window list holds one dashboard window and one window per sheet.

```xml
  <preferences>
    <preference name='ui.encoding.shelf.height' value='24' />
    <preference name='ui.shelf.height' value='26' />
```
